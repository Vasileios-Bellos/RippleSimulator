Functions and Properties

rippleSimulator launches the interactive gravity-capillary ripple simulator application. app.RippleSimulatorApp provides the class-based interface. Use the following functions and properties to set up experiments, create sources, read physical quantities, and control the presentation from MATLAB code.

Function and class reference

rippleSimulator

Launch the application

Syntax

rippleSimulator()
app = rippleSimulator()
app = rippleSimulator(Name=Value)

Description

rippleSimulator() opens the default gravity-scale water experiment. Click the surface to create a ripple, or choose commands from the menus and axes toolbar. Closing the figure releases the app's resources.

app = rippleSimulator() also returns the owning app.RippleSimulatorApp handle. Use it to change properties, create sources, and inspect physical data.

app = rippleSimulator(Name=Value) forwards name-value arguments to the class constructor.

The only required MathWorks product is MATLAB R2022a or later. No additional toolboxes are required. See Installation and requirements for setup instructions and troubleshooting.

Examples

Explore a capillary-scale disturbance

Create a localized disturbance in the Capillary water experiment.

app = rippleSimulator(Setup="Capillary");
app.addRipple([0, 0]);

Surface tension dominates over gravity at the Capillary setup's characteristic wavelength. The Gaussian pressure impulse excites a spectrum of wavelengths, producing a dispersive wave packet with concentric rings.

Water at 20 °C, 8.72 ms after a central impulse; 5 mm characteristic wavelength, 32.5 × 32.5 mm domain, 201 × 201 grid, and 100x height scale.

Close the app when finished:

app.close();

Name-Value Arguments

Argument Description
Setup "Gravity" (default), "Balanced", or "Capillary"; select a scaled water experiment.
GridResolution Integer from 51 to 801; default 201. Must also satisfy spatial sampling requirements.
Visible "on" or "off"; default "on".
AutomaticUpdates Logical scalar; default true. Set false to call update explicitly.
Paused Logical scalar; default false. Set true to start paused at physical time zero. Setting the Paused property to false resumes time; automatic updates start only if AutomaticUpdates=true.
TimeSource Optional function handle returning a finite, monotonic scalar time in seconds. The default uses MATLAB's elapsed timer.
ReflectionsEnabled Logical scalar; default false. Set true to start with reflecting boundaries.
ReflectionCoefficient Real scalar from 0 to 1; default 1. Reflected amplitude fraction when wave reflections are enabled.

Output Arguments

app – Owning application

Scalar app.RippleSimulatorApp handle. The handle becomes invalid when the application closes.

Caution: An output variable named app shadows the app namespace. This does not affect calls to object methods, such as app.addRipple. Use a different variable name when calling app.RippleSimulatorApp(...) directly. If app already exists in the Command Window workspace, close the application and run clear app before accessing the namespace.

app.RippleSimulatorApp

Create a Ripple Simulator application object

Syntax

simulator = app.RippleSimulatorApp()
simulator = app.RippleSimulatorApp(Name=Value)

simulator.Property = value

Description

app.RippleSimulatorApp() constructs the application object and creates its interface. The object owns its figure, controls, elapsed-time clock, and wave model. Public properties control the experiment and its presentation; menu commands use the same property setters. An accepted change updates the affected components before notifying observers.

The model represents linear waves on an infinitely deep, homogeneous Newtonian fluid with a clean free surface. The unmodified response includes gravity, surface tension, dispersion, and viscosity. A finite-duration envelope returns each source to exact stillness. See Physics for the governing equations and the assumptions required for quantitative interpretation.

The class has handle semantics and cannot be subclassed. Its app.internal components are implementation details, not supported public interfaces.

Examples

Change presentation without changing the physical field

Freeze the experiment at its initial time, add an impulse, and compare a physical snapshot before and after changing the rendering.

simulator = app.RippleSimulatorApp(Visible="off", AutomaticUpdates=false, TimeSource=@() 0);
simulator.addRipple([0, 0]);
before = simulator.snapshot(Derivatives=true);
simulator.Wireframe = true;
simulator.HeightScale = 1000;
after = simulator.snapshot(Derivatives=true);
isequal(before, after)
ans =
  logical
   1

The impulse initially has zero elevation and nonzero vertical velocity. The unchanged snapshot verifies that display settings do not alter either field.

simulator.close();

addRipple

Apply one localized source at physical coordinates

Syntax

identifier = addRipple(simulator,position)
identifier = simulator.addRipple(position)

Description

identifier = simulator.addRipple(position) applies the current source at position = [x, y], measured in meters from the domain's center. The input retains its physical start time, wavelength, pressure strength, and excitation method. Changing these settings later affects subsequent inputs only.

The position must lie within the observation domain. Sources use the stated small-disturbance model. A pressure impulse starts with zero elevation and a velocity disturbance; its elevation develops during playback.

Examples

Create simultaneous disturbances

Use a fixed time source for exactly simultaneous inputs without relying on the speed of sequential commands.

simulator = app.RippleSimulatorApp(Visible="off", AutomaticUpdates=false, TimeSource=@() 0);
first = simulator.addRipple([-0.1, 0]);
second = simulator.addRipple([0.1, 0]);
info = simulator.describe();
[first, second; info.Simulation.Events.Time]
ans =
     1     2
     0     0

The two sources have equal pressure strength and start time. Their wave fields are superimposed linearly. For an interactive experiment, pause before adding both sources, then resume playback.

simulator.close();

Input Arguments

simulator – Application

Scalar app.RippleSimulatorApp handle.

position – Source center

Finite, real, numeric 1-by-2 row vector in meters. Each coordinate must lie between -simulator.DomainSize/2 and simulator.DomainSize/2, including the endpoints.

Output Arguments

identifier – Accepted input number

Positive scalar integer stored as double. Numbers increase within the current experiment; a new physical experiment starts a new input sequence.

rain

Schedule twenty localized sources

Syntax

rain(simulator)
simulator.rain()

Description

simulator.rain() schedules twenty inputs at positions drawn uniformly from the observation domain and placed at the nearest grid nodes. The first is issued immediately, followed by nineteen inputs spaced by 0.05 seconds of elapsed real time while playback runs. Each event uses the same source operation as a manual click. By default, its pressure strength is also the same. RainStrengthScale multiplies the selected pressure strength for rain. Each burst retains the multiplier selected when it was scheduled; wavelength, excitation method, and pressure strength follow their settings at each input time.

The source definition gives the applied pressure impulse and its physical units. Rain demonstrates the superposition of localized gravity-capillary waves. The source idealization represents wave excitation without resolving drop deformation, impact cavities, or splashing. Measured ring-wave scales provide experimental context for the resulting elevations and propagation speeds.

Pausing suspends the remaining schedule. Rain requests are ignored while paused. A delayed update processes overdue inputs at their intended timestamps. Additional bursts retain the pending drops and overlap their schedules. clear cancels unissued inputs. RandomSeed controls a private random number stream. Rain generation does not change the state of MATLAB's global random number stream.

When sound is enabled during playback, each burst plays one recording of rain striking water. Mute or pause stops the recording. Repeated bursts can overlap their recordings as well as their wave fields.

Examples

Repeat a burst's positions

Reinitialize the private seed to repeat the positions. Clearing alone retains the stream's progression.

simulator = app.RippleSimulatorApp(Visible="off", AutomaticUpdates=false, TimeSource=@() 0);
simulator.RandomSeed = 42;
simulator.rain();
first = simulator.describe();
simulator.clear();
simulator.RandomSeed = 42;
simulator.rain();
second = simulator.describe();
isequal(first.Simulation.Events.Position, second.Simulation.Events.Position)
ans =
  logical
   1

Only the first source is due at this fixed time. The remaining nineteen positions are reserved for later playback.

simulator.close();

Input Arguments

simulator – Application

Scalar app.RippleSimulatorApp handle.

snapshot

Retrieve the wave field data at the current simulation time

Syntax

waveField = snapshot(simulator)
waveField = snapshot(simulator,Derivatives=true)
waveField = simulator.snapshot(Name=Value)

Description

waveField = simulator.snapshot() retrieves the wave field data at the current simulation time. The Time field records the last processed simulation time. Call update first when newly elapsed time must be processed. Display exaggeration and camera settings do not enter the returned quantities.

waveField = simulator.snapshot(Derivatives=true) also returns vertical surface velocity and the horizontal surface-elevation gradients, ∂η/∂x and ∂η/∂y. Velocity includes the derivative of the finite-duration envelope during the settling interval.

Examples

Inspect the wave field

Pause an open application before reading a fixed wave state:

simulator.Paused = true;
waveField = simulator.snapshot(Derivatives=true);

The wave field inspection example animates the complete time history and describes the inspectWaveField options.

Input Arguments

simulator – Application

Scalar app.RippleSimulatorApp handle.

Name-Value Arguments

Derivatives – Include vertical velocity and elevation gradients

false (default) or true, specified as a logical scalar or numeric 0 or 1.

Limitations

Maxima over the grid nodes are not certified continuous-space extrema. Compare finer grids when small features or slopes matter.

IsAtRest describes the represented surface. It does not characterize residual vorticity throughout the full fluid depth. The finite-duration envelope makes each source contribution exactly zero at its deadline.

describe

Read experiment settings and material provenance

Syntax

info = describe(simulator)
info = simulator.describe()

Description

info = simulator.describe() returns the experiment configuration from one processed state. It does not advance time. Fluid properties include SI unit names and source provenance.

Use the record to identify the fluid, source definition, physical dimensions, playback rate, height scale, source settings, and simulation time. It is an inspection record, not a serialized app that can be loaded to resume an experiment.

Examples

Inspect the scaled experiment

simulator = app.RippleSimulatorApp(Visible="off", AutomaticUpdates=false, TimeSource=@() 0);
info = simulator.describe();
fprintf("Domain: %.2f m\nGrid: %d nodes per side\nHeight scale: %gx\n", ...
    info.DomainSizeMeters, info.GridResolution, info.HeightScale);
Domain: 0.65 m
Grid: 201 nodes per side
Height scale: 100x

The domain spans 0.65 × 0.65 m. The rendering uses 201 nodes per side and a height multiplier of 100; the multiplier is absent from snapshot values.

simulator.close();

Input Arguments

simulator – Application

Scalar app.RippleSimulatorApp handle.

Output Arguments

info – Configuration record

Scalar structure. Principal groups are Fluid, Source, Display, Camera, and Simulation. Other fields report material, domain width, grid resolution, playback rate, height scale, pause state, pending rain, rain multiplier, seed, boundary setting, and application state.

Display.BackgroundColor records the viewing area's current RGB background.

The Simulation.Events records identify active source positions, start times, pressure strengths, and source definitions. Use these alongside the material record when comparing experiments. Physical quantities are returned by snapshot.

update

Process elapsed time and update the existing surface

Syntax

update(simulator)
simulator.update()

Description

simulator.update() samples the monotonic time source, processes due rain events at their scheduled timestamps, and renders the current wave state. Use it for an app created with AutomaticUpdates=false. Automatic playback calls the same update route.

An update is an observation of elapsed time, not a fixed physical integration step. Fewer rendered frames do not slow the waves. Pausing stops the simulation and rain schedule; time spent preparing a configuration is excluded from playback.

Examples

Update without advancing the clock

simulator = app.RippleSimulatorApp(Visible="off", AutomaticUpdates=false, TimeSource=@() 0);
simulator.addRipple([0, 0]);
before = simulator.snapshot(Derivatives=true);
simulator.update();
after = simulator.snapshot(Derivatives=true);
isequal(before, after)
ans =
  logical
   1

With no elapsed time, another update does not advance the physical state. The wave field inspection example uses a controllable clock to sample the wave field at uniformly spaced times.

simulator.close();

Input Arguments

simulator – Application

Scalar app.RippleSimulatorApp handle.

The clock accounts for pause intervals and changes in rate. A rate change affects subsequent playback and does not rescale elapsed simulation time. Source responses are sampled at their physical ages.

applySetup

Start a new gravity, balanced, or capillary experiment

Syntax

applySetup(simulator,name)
simulator.applySetup(name)

Description

simulator.applySetup(name) selects a scaled water experiment and clears existing waves and pending rain. Each preset uses water at 20 °C. The gravity setup uses a 50 mm characteristic wavelength in a 650 × 650 mm domain; the balanced and capillary setups span 6.5 characteristic wavelengths. Gravity and Balanced start at 0.25x playback; Capillary starts at 0.10x. The current grid must satisfy the selected source's sampling limits.

The preset restores its pressure strength and height scale. The selected boundary type, camera, and pause state are preserved.

Examples

Select the capillary scale

simulator = app.RippleSimulatorApp(Visible="off", AutomaticUpdates=false, TimeSource=@() 0);
simulator.applySetup("Capillary");
simulator.DomainSize/simulator.Wavelength
ans =
    6.5000

The physical dimensions change together. The visible framing stays comparable while the bottom panel reports the new domain size. Changing Wavelength alone instead retains the domain and affects only new sources.

simulator.close();

Input Arguments

simulator – Application

Scalar app.RippleSimulatorApp handle.

name – Scaled setup

"Gravity", "Balanced", or "Capillary", as a string scalar or character vector. Both gravity and surface tension contribute to the wave motion in every setup.

clear

Clear waves and cancel pending rain

Syntax

clear(simulator)
simulator.clear()

Description

simulator.clear() removes active sources and pending rain. The surface elevation, vertical velocity, and horizontal elevation gradients become exactly zero. Physical time, settings, camera, pause state, and the state of the private random number stream are preserved. Use reset to restore the complete default experiment.

Examples

Cancel a scheduled burst

simulator = app.RippleSimulatorApp(Visible="off", AutomaticUpdates=false, TimeSource=@() 0);
simulator.rain();
simulator.clear();
info = simulator.describe();
[simulator.IsAtRest, info.PendingRain]
ans =
     1     0

simulator.close();

Scalar app.RippleSimulatorApp handle.

reset

Restore the default experiment and presentation

Syntax

reset(simulator)
simulator.reset()

Description

simulator.reset() restores the gravity-scale water experiment, 201-node grid, open boundaries, pressure impulse, original camera, display defaults, playback rate, and initial private rain seed. Existing waves and scheduled rain are cleared. Playback resumes from zero simulation time. The viewing-area background follows the figure theme, or uses white on releases without theme support.

Examples

Restore display and physical defaults

simulator = app.RippleSimulatorApp(Visible="off", AutomaticUpdates=false, TimeSource=@() 0);
simulator.Wireframe = true;
simulator.Paused = true;
simulator.reset();

capture

Export the application view to a PNG image

Syntax

capture(simulator,filename)

simulator.capture()

Description

simulator.capture(filename) saves the currently displayed application frame.

simulator.capture() opens a filename dialog after copying the displayed pixels. The saved image therefore represents the view when capture was requested, regardless of time spent choosing the filename.

Visible controls and panels are included; the native menu bar and window border are not. The filename must end in .png. Existing files can be overwritten; use a distinct filename to preserve previous captures.

Choose View > Save Screenshot... or press Ctrl+S (Command+S on macOS) to capture the current view. The shortcut also works in full screen.

Customization

Custom fluid properties can be supplied through FluidProperties or Experiment > Material > Custom > Define properties.... Additional named presets are implemented in the source code. See Custom fluids for the property inputs and Constitutive model and rheology for the material assumptions.

Add a fluid preset

  1. Define the material properties. Add a function in +app/+internal/+materials/ that returns an app.internal.materials.Fluid object. The existing oliveOil.m definition provides a compact template. The constructor accepts the material name, temperature in degrees Celsius, density in kg/m³, dynamic viscosity in Pa·s, surface tension in N/m, and a reference string, in that order. The reference identifies the property sources and measurement conditions. Kinematic viscosity is calculated from the dynamic viscosity and density.

  2. Integrate the preset into the application. In +app/RippleSimulatorApp.m, extend the accepted values and selection branch in set.Material. The branch calls the new material function and specifies the characteristic wavelength, pressure strength, and height scale. get.Material maps the fluid's Name to the same preset identifier. The local materialStyle function supplies its surface appearance. These settings are applied whenever the material is selected, including when it is selected again. Wavelength is specified in meters and PressureImpulse in Pa·s; the controls display millimeters and mPa·s.

  3. Add the menu entry. In createMenus in +app/+internal/+ui/Controls.m, add a material choice using the same preset identifier. The existing choices pass the material action and the Material property to obj.choice. This routes menu selections through the property setter and synchronizes the checkmark with the selected material.

Preset properties apply at their specified temperature. A temperature-dependent preset also requires a property correlation and corresponding support in set.Temperature and the temperature menu; a single-temperature property record does not define that dependence. The material assumptions and supporting data are described in Materials.

tests/+unit/FluidPropertiesTest.m checks property values, units, correlations, and input ranges. tests/+integration/MaterialPresetsTest.m checks material selection and restoration of experiment settings. Additional presets require corresponding cases for their property values and selection behavior.

Tests

After modifying the source code, run the test suite from the project folder:

results = runtests("tests", IncludeSubfolders=true);
assertSuccess(results);

The suite uses matlab.unittest.TestCase classes. runtests returns the individual test results; assertSuccess raises an error if any test fails, so an automated run can report the failure to its caller. See the MathWorks documentation for more details.

Test group Coverage
Unit Physical limits, fluid properties, elapsed-time behavior, and packaged audio
Integration Source superposition, boundary conditions, material selection, graphics retention, timer cleanup, and the examples' wave-field histories and dispersion data

Run a test group by specifying its tag:

results = runtests("tests", IncludeSubfolders=true, Tag="Unit");
assertSuccess(results);

Use Tag="Integration" to select the integration tests. An individual test class can also be run by its file path:

results = runtests("tests/+integration/MaterialPresetsTest.m");
assertSuccess(results);

Application tests create hidden figures and release their figures and timers. The support namespace in tests/+support/ contains the shared test base class and a controllable clock for reproducible timing checks.
